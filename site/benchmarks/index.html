Benchmarks for evaluating the safety of tool-using LLM agents

What each benchmark
actually measures.

Nine benchmarks, one comparison,
and where OpenART fits.

Tool-using LLM agent safety benchmarks evaluate whether an agent can use tools, files, services, or a desktop without causing prohibited side effects. They differ in environment type, task horizon, attack model, and whether safety is judged from a final answer or from the full execution trace. This page lists the widely used benchmarks with links to their papers, reproduces the OpenART paper's task-complexity comparison, and states where OpenART fits — without ranking claims.

03OpenART

Where OpenART fits.

OpenART evaluates the executable environment rather than treating a single prompt as the entire test. The benign task and a hidden safety contract remain fixed while target-visible state changes during execution. Numbers below are from the paper and the released datasets.

Difference from static benchmarks. In InjecAgent, AgentDojo, and ToolEmu-style settings, the attack is embedded in the task and the environment is reset between episodes. In OpenART, a black-box attack policy (EMHA) coordinates authorized state transitions across eight target-visible surfaces while the task and hidden safety contract stay fixed. Safety is judged over the full execution trace, not a final answer.

Difference within the long-horizon group. DTap also uses stateful environments with longer workflows. OpenART's released set is larger (10,150 released tasks) and its evaluation matrix spans 15 deployed agent runtimes × 5 foundation models, reporting both benign completion and strict attack success per setting.

Strict ASR definition. Strict attack success rate counts an attack as successful only when both a deterministic evaluator and an LLM judge confirm it. The pooled 85.0% figure aggregates 75 agent–model settings under the EMHA attacker; it is a property of that attack and protocol, not a model-safety score in isolation.

QUESTIONS

Common questions.

What are the top benchmarks for evaluating the safety of tool-using LLM agents?

Widely used benchmarks include Agent-SafetyBench, AgentDojo, AgentHarm, InjecAgent, ToolEmu, R-Judge, and SafeToolBench. Newer long-horizon benchmarks include DTap and OpenART. They differ in environment type, task horizon, and whether safety is judged from a final answer or the full trace.

What is an agent safety benchmark?

An agent safety benchmark measures whether an LLM agent that uses tools, files, services, or a desktop causes prohibited side effects while completing a task. It provides tasks, an environment, and an evaluator that judges safety from the agent's behavior.

How does OpenART differ from single-turn prompt-injection benchmarks?

OpenART tasks are long-horizon (median 97 tool calls) and judged over full execution traces. The benign task and a hidden safety contract stay fixed while target-visible environment state changes mid-run, so failures can emerge from sequences of individually benign actions rather than from a single decision.

What is long-horizon agent safety?

Long-horizon agent safety asks whether an agent stays safe across tasks that unfold over many steps and tool calls, where early state changes can influence decisions far into the future. OpenART reports a median propagation distance of 37 target actions between consuming evolved state and a first unsafe action, with an interquartile range of 20 to 66.

What is environment evolution?

Environment evolution changes target-visible state — workspace files, tools, services, plan, or memory — during a run while the task and hidden safety contract stay fixed. OpenART uses it as its core red-teaming protocol through the EMHA attack policy, a black-box search over authorized state transitions.
